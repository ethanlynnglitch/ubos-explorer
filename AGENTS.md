# UBOS Explorer — project notes

Small explorer for Uganda Bureau of Statistics (UBOS) GDP statistics.

## Environment

Python 3.12 in `.venv`. Dependencies actually used by the ingestion pipeline:

| Package | Why |
|---|---|
| `openpyxl` | reads the four `.xlsx` quarterly workbooks |
| `xlrd==2.0.1` | reads the legacy BIFF8 `.xls` annual workbook (openpyxl/pandas cannot) |
| `pandas` + `pyarrow` | Parquet output |
| `PyYAML` | `config/sources.yml` |

```bash
.venv/bin/pip install openpyxl xlrd==2.0.1 pandas pyarrow PyYAML
```

## Run the ingestion pipeline

```bash
PYTHONPATH=src .venv/bin/python -m ubos_explorer.pipeline
```

Exit code is `1` if any QA check FAILs, `2` if an activity row label could not be
matched to the crosswalk (nothing is written in that case), `0` otherwise.

Outputs:

- `data/processed/gdp_observations.parquet` — fact table, all release vintages, `is_current` flag
- `data/processed/source_blocks.parquet` — extraction manifest incl. `file_sha256` per workbook
- `data/processed/rejects.parquet` — every cell that did not become an observation, with reason
- `reports/ingestion_qa.md` — validation report

## Build the DuckDB analytical layer

```bash
PYTHONPATH=src .venv/bin/python -m ubos_explorer.warehouse           # rebuild data/ubos.duckdb
PYTHONPATH=src .venv/bin/python -m ubos_explorer.warehouse --check   # verify, don't rebuild
```

`data/ubos.duckdb` is a **derived, disposable artifact** rebuilt from scratch on
every run; deleting it loses nothing. Schema lives in
`src/ubos_explorer/sql/{schema.sql,views.sql}`. Exit code is `1` if an integrity
check fails or if a Parquet input has changed since the build (staleness).

Query the views, not the raw tables: `v_observation`, `v_observation_current`,
`v_gdp_annual`, `v_gdp_quarterly`, `v_gdp_sectors`, `v_activity_tree`,
`v_lineage`, `v_release_comparison`.

## Run the dashboard

```bash
PYTHONPATH=src .venv/bin/streamlit run app/Home.py
```

Multi-page Streamlit app (Altair charts) reading `data/ubos.duckdb` read-only via
`src/ubos_explorer/queries.py`. Pages: Overview, By activity, Growth, Quarterly
series, Data & lineage. Requires the warehouse to exist; it fails with an
actionable message if not.

- `queries.py` is deliberately Streamlit-free (pure DuckDB -> DataFrame) so it
  stays testable; caching lives in `app/_bootstrap.py`.
- The app shows the **latest UBOS release only** (`v_observation_current`).
- Selector options are derived from `available_series()`, so combinations UBOS
  does not publish (e.g. current-price growth) cannot be selected.

Smoke-test every page headlessly:

```bash
PYTHONPATH=src:app .venv/bin/python -c "
from streamlit.testing.v1 import AppTest
for p in ['app/Home.py','app/pages/1_By_activity.py','app/pages/2_Growth.py',
          'app/pages/3_Quarterly_series.py','app/pages/4_Data_and_lineage.py']:
    at = AppTest.from_file(p, default_timeout=90).run()
    print(p, 'FAIL' if at.exception else 'OK')"
```

## Hard rules

- **`data/raw/` is read-only.** Never modify, rename, move or delete the original
  UBOS workbooks. The pipeline only ever opens them for reading and records a
  sha256 of each.
- **`growth_basis` must stay null** for growth observations. The workbooks label
  those tables only "PERCENTAGE CHANGE" and do not say whether the change is
  year-on-year or quarter-on-quarter. Do not infer it from value magnitudes;
  populate it only from authoritative UBOS documentation.
- **An unmatched activity label is an error, not a skip.** Add a verified alias to
  `src/ubos_explorer/config/activities.csv` after confirming what the row actually
  is (e.g. by checking that components still sum to their sector aggregate).
- Adding a new UBOS release should be a `config/sources.yml` edit, not new code.
- **Never `SUM()` across `activity_level`** — aggregates (`total`, `sector`) and their
  components coexist in the fact table. Filter to one level first.
- **Never sum quarters for a fiscal year where `has_four_quarters` is false** (2025/26
  currently has three), and do not recompute `is_current` in SQL — it is authoritative
  from the pipeline, and `release_date` varies *within* a release_id.

## Not built yet (deliberately)

Web scraping / UBOS website discovery, API, authentication, deployment.
Out of scope for v1 data-wise: expenditure-side GDP, IPD/deflators, `%share`
tables, and the formal/informal/market/non-market/own-account/institutional-sector
breakdowns. The dashboard also does not surface superseded release vintages,
though they remain in the database (`v_release_comparison`).

## Assumptions carried in code

- Uganda's fiscal year runs July–June (`normalize.FY_START_MONTH`), used to derive
  `period_start`/`period_end`. Corroborated by the calendar-year header row of the
  UBOS expenditure sheets but not stated in the GDP sheets themselves.
